# SUPER Reference Architectures

SUPER is informed by a broad reference ecosystem. References are used for architectural study, capability discovery, and design inspiration; they are not a blanket authorization to copy code or content.

## Primary References

- `affaan-m/ECC` — agent/skill/command organization, engineering workflows, hooks, memory, evaluation, security, and harness-oriented patterns.
- `garrytan/gstack` — opinionated engineering workflow skills, persistent browser infrastructure, security boundaries, verification, and operational tooling.
- `deepseek-ai/deepseek-harness` — agent harness and execution patterns.
- `langchain-ai/langchain` — model/tool/agent orchestration abstractions and ecosystem design.
- `Comfy-Org/ComfyUI` — graph-based composition and execution of complex workflows.
- `openai/codex` — coding-agent and tool-execution patterns.
- `google-gemini/gemini-cli` — CLI-oriented agent interaction and extensibility patterns.
- `karpathy/autoresearch` — autonomous experimentation and measurable iteration.
- `Graphify-Labs/graphify` — graph-oriented project/code knowledge concepts.
- `ashishpatel26/500-AI-Agent-Projects` — breadth of real-world agent use cases and domain coverage.

## Skills / Design References

The broader reference set also includes UI/UX skill collections, agent-skill registries, scientific/finance/data skills, design systems, office/document skills, browser and scraping tools, Blender/3D skills, and other domain-specific repositories supplied during SUPER planning.

## Design Rule

SUPER should extract durable architectural ideas and reimplement the necessary behavior under compatible licensing and original implementation. Each adopted external dependency or copied artifact must undergo provenance and license review.

## What We Optimize For

We do not optimize for matching another project's file count, agent count, or marketing claims. SUPER optimizes for:

1. real execution
2. composability
3. reliability
4. security
5. verification
6. observability
7. extensibility
8. measurable improvement
9. broad domain coverage
10. a coherent developer experience
