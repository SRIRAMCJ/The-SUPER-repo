## This PR's contract

- Explicit task capabilities are an **ordered execution pipeline**. Preserve order
  and duplicate occurrences; do not sort it as a set. The aggregate requirement
  list is deduplicated and sorted for inspection.
- An empty explicit list falls back to `agent`; malformed lists/agent IDs are rejected.
  Planner/admission tasks without an executor are not ready.
- Admission validates graph IDs/order/dependencies using the executor's validator.
  It rechecks actual task capabilities even if the summary omits them.
- Governance is synchronous at these interfaces and must return `allowed === true`.
  Missing/malformed decisions block; thrown admission governance errors block.
  This does not fix the separate async-policy bug inside `PolicyEngine` (A03).
- Age validation uses a single clock reading. With a configured age bound, missing,
  unparsable and future timestamps are invalid. The default remains no age bound.
- `execute` snapshots the plan before admission; caller changes cannot replace its
  admitted graph through the admission event. Capability revocation during a later
  running task still requires execution-time policy enforcement.
- Tool output is preserved. The existing echo test was corrected to expect
  `{value: 7}`, which is exactly what its echo handler returns; no runtime data was
  unwrapped or discarded to satisfy the old scalar expectation.

Prior branch work was inspected: `db80e58` preserved capability lists and `18224fe`
fixed the clock call. This PR reconciles those ideas onto current main with stricter
validation, preserved execution order, shared capability selection and regressions.
The plan fingerprint remains a non-cryptographic diagnostic checksum, not authentication.
